> **适用场景**：Deepin / Ubuntu 等 Linux 系统，板载内存（不可更换）在 MemTest86 中反复报出相同地址的错误，导致系统随机崩溃、花屏、死机或卡在空白壁纸。
>
> **核心思路**：用内核 `memmap` 参数把坏块从可用内存中挖掉，让系统绕开它。
>
> **风险提示**：这是软件层规避方案，不是修复。坏块可能随老化扩散，操作前务必先备份数据。

---

## 一、判断是否为固定物理坏块

| 特征 | 说明 |
|---|---|
| 地址稳定 | 多次独立测试，报错地址完全一致 |
| 数量不扩散 | 错误总数保持低位，不持续增长 |
| 降频无效 | 降低内存频率后仍报同样错误 |

三条都满足 → 进入屏蔽流程。

若错误地址每次不同、数量爆炸式增长 → 内存整体劣化，屏蔽无效，考虑送修。

## 二、制作 MemTest86 启动 U 盘

### 准备

- 容量 ≥ 1GB 的 U 盘（**数据会被全部清空，提前备份**）
- 一台可正常上网的电脑
- MemTest86 官网免费版（Free Edition），功能完整，仅缺企业级报告

### 下载

官网点击 Download Free Version，下载 ZIP 并**完整解压**。

### 写入 U 盘

**Windows**

运行 `imageUSB.exe` → Refresh 刷新列表 → 勾选 U 盘（**务必确认设备号，避免误写系统盘**）→ 选 Write image to USB drive → 镜像保持默认 → Write，约 1 分钟完成。

**Linux / macOS**

```bash
# 确认 U 盘设备名（千万别写错）
lsblk -p -o NAME,VENDOR,MODEL,SIZE,TYPE,SERIAL

# 卸载 U 盘所有分区
sudo umount /dev/sdX?*

# 写入镜像（注意是设备名，不是分区名）
sudo dd if=memtest86-usb.img of=/dev/sdX bs=4M status=progress conv=fsync
```

**两个正常现象**：写入后 U 盘容量只显示 254MB、在 Windows 里打不开，都是正常的，因为它是 Linux 核心。

想恢复 U 盘容量：重新运行 `imageUSB.exe`，选 Reformat USB drive。

## 三、MemTest86 精确定位坏块

### 从 U 盘启动

插入 U 盘重启，按主板快捷键进入一次性启动菜单：

| 品牌 | 按键 |
|---|---|
| Dell / Lenovo / Gigabyte | F12 |
| MSI | F11 |
| ASUS | F8 |
| HP | Esc |

选择以 `UEFI:` 开头的 U 盘项。新版镜像已带微软签名，多数机器无需关闭 Secure Boot；若被拦截，临时关闭即可。

部分华硕主板 BIOS 内置 MemTest86，可直接在 BIOS 顶部工具栏运行。

### 配置测试项（关键优化）

免费版默认循环 4 轮，耗时长且容易触发错误上限中止。建议只跑两个高灵敏度测试项：

1. 倒计时结束前动一下鼠标，进入主界面
2. 主菜单 → 测试选择（T）
3. 按 `T` 键全不选，再单独勾选：
   - **Test 4：Modulo 20**
   - **Test 7：Moving Inversions**
4. 回主菜单 → 选项（E）→ 把「错误限制 / 错误上限」改为 `100000` 或禁用
5. 主菜单 → 开始测试（S）

### 记录结果

测试结束停在结果摘要页，重点记录：

- 最小错误地址（如 `0x20C1E4128`）
- 最大错误地址（如 `0x226BE0374`）
- 错误总数、失败的测试项编号、报错的 CPU 核心

按 `Y` 可保存 HTML 报告到 U 盘。

> **建议跑两轮，确认地址完全一致再动手。** MemTest86 的结果本身也可能抖动，需重复验证。

## 四、屏蔽坏块

### 地址换算规则

报错地址不能直接用，必须向下对齐到 2MB 边界：

| 报错地址 | 屏蔽起始地址 |
|---|---|
| `0x20C1E4128` | `0x20C000000` |
| `0x226BE0374` | `0x226000000` |

建议屏蔽比实际坏块稍大的区域，因为周边地址后续也很可能失效。

### 修改 GRUB 参数

```bash
sudo nano /etc/default/grub
```

修改 `GRUB_CMDLINE_LINUX_DEFAULT`：

```
GRUB_CMDLINE_LINUX_DEFAULT="quiet splash nokaslr memmap=2M#0x20C000000 memmap=2M#0x226000000"
```

保存（`Ctrl+O` → 回车 → `Ctrl+X`），然后：

```bash
sudo update-grub
sudo reboot
```

### memmap 语法详解

内核提供四种相关写法：

| 语法 | 含义 |
|---|---|
| `memmap=nn[KMG]@ss[KMG]` | 强制使用指定区域 |
| `memmap=nn[KMG]$ss[KMG]` | 标记为保留（reserved） |
| `memmap=nn[KMG]!ss[KMG]` | 标记为持久内存（persistent） |
| `memmap=nn[KMG]#ss[KMG]` | 标记为 ACPI 数据 |

### 三个关键坑

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 用 `$` 作分隔符 | GRUB 把 `$` 当变量解析，参数被吃掉，导致卡在空白壁纸无法进系统 | 用 `#` 或 `!` 代替 `$` |
| 忘记 `nokaslr` | 内核随机加载地址可能落进被挖掉的洞里，引发死锁 | 加上 `nokaslr` |
| 直接用报错地址 | 未对齐，屏蔽不生效 | 必须向下对齐到 2MB |

官方文档确实提到：某些引导程序（如 Grub2）需要在 `$` 前加转义符，否则 `$` 和后面的数字会被吞掉。更严谨的写法是 `memmap=2M\$0x20C000000`（`$` 要转义，转义符本身在 shell 里也要转义）。

**但实测改用 `#` 是最省心的方案。**

### 关于 GRUB_BADRAM 的替代方案

`/etc/default/grub` 中也可用 `GRUB_BADRAM=""`，直接粘贴 MemTest86+ 输出的 BadRAM 模式，省事。

**缺点是**：一旦写错（拼写或 bug），会直接搞坏引导程序，必须用救援介质修复。

而 `memmap` 方案虽麻烦一点，却能在 GRUB 启动提示符里按 `e` 编辑启动项当场救回来。

**所以推荐 `memmap`。**

## 五、应急恢复：改坏了怎么办

系统本身没有损坏，只是启动参数错了。按以下顺序恢复。

### 方法一：GRUB 临时编辑（首选）

1. 重启，在 GRUB 菜单按 `e`
2. 找到以 `linux` / `vmlinuz-` 开头的长行
3. 删掉 `memmap=...` 和 `memtest=4`，只保留 `quiet splash` 和 `root=UUID=...`
4. 按 `Ctrl+X` 或 F10 启动

> **别选错条目**：`Deepin Restore` 是恢复模式（参数含 `boot=live` 和 `filesystem.squashfs`），要选普通的 `Deepin` 项。若菜单一闪而过，开机时按住 `Shift` 或连按 `Esc` 调出。

### 方法二：单用户模式

在 `linux` 行末加 `init=/bin/bash`，启动后：

```bash
mount -o remount,rw /
nano /etc/default/grub      # 改回正常参数
update-grub
exec /sbin/init
```

### 方法三：U 盘救援

用 Live U 盘启动进入试用环境：

```bash
sudo fdisk -l                       # 找到根分区
sudo mount /dev/nvme0n1p2 /mnt
sudo nano /mnt/etc/default/grub     # 删掉 memmap 参数
sudo umount /mnt
```

## 六、验证屏蔽是否生效

### 1. 确认参数已加载

```bash
cat /proc/cmdline
```

应能看到 `memmap=2M#0x20C000000 memmap=2M#0x226000000`。

### 2. 确认坏块被保留（最可靠的判据）

```bash
sudo cat /proc/iomem | grep -iE "20c0|2260"
```

出现 `Persistent Memory (legacy)` = 屏蔽成功。

### 3. 确认内存减少

```bash
free -h
```

可用内存应比之前少约 4MB（2MB × 2 处）。

### 4. 检查有无新坏块

```bash
sudo dmesg | grep -iE "bad page|memtest|e820|reserved"
```

- `0 bad pages found` → 除已知坏块外内存干净
- 无相关输出 → 可能是该内核未编译 `CONFIG_MEMTEST`，此时以第 2 步的 iomem 结果为准

补充：`memtest=4` 参数会让内核在启动时做 4 轮内存扫描，自动把发现的坏区标记为不可用。64GB 内存大约耗时半分钟。

### 5. 不要用 MemTest86 验证屏蔽效果

MemTest86 独立于操作系统，不读取内核 `memmap` 参数，仍会照常报出那两个地址的错误，容易造成「屏蔽失败」的误判。

### 6. 可选：压力测试

```bash
sudo apt install memtester
memtester 12G 2
```

若报「无法获取锁 /var/lib/dpkg/lock-frontend」，说明有更新器或商店占用：

```bash
sudo lsof /var/lib/dpkg/lock-frontend    # 先看谁占用
```

关闭图形化更新器后重试；或确认无安装任务时：

```bash
sudo rm -f /var/lib/dpkg/lock-frontend /var/lib/dpkg/lock
sudo apt --fix-broken install
```

这一步属于锦上添花。若 MemTest86 两次独立测试地址一致、屏蔽参数已生效、系统能正常进桌面，就已可以判定处理成功。

## 七、后续维护建议

**1. 立即备份。** Git 远端 + 移动硬盘双份。坏块虽稳定，但老化可能继续。

**2. 释放核显占用。** BIOS 中把 `UMA Frame Buffer Size` 从 2G 调低（最低可到 128M），可多释放近 2G 内存。

路径通常为 `Advanced → AMD CBS → NBIO Common Options → GFX Configuration → UMA Frame Buffer Size`，或 `Config → Display → UMA Frame Buffer Size`，改完按 F10 / F4 保存重启。

> 核显不自带显存，是共享系统内存。调小显存会释放内存，但图形性能可能下降。

**3. 清灰换硅脂。** 高温是内存劣化的加速器（实测 CPU 峰值曾达 101℃）。

**4. 监控复发。** 若再次出现花屏、随机崩溃，重跑 MemTest86，看坏块是否扩散，必要时更新屏蔽清单。

**5. 认清局限。** 这是临时规避方案。如果错误增长到成百上千，最稳妥的做法仍是更换内存。

## 八、完整流程速查

```
制作 MemTest86 启动 U 盘（imageUSB.exe 或 dd）
        ↓
BIOS 从 U 盘启动（F12 / F11 / F8 / Esc）
        ↓
只跑 Test 4 + Test 7，跑两轮确认地址一致
        ↓
地址向下对齐到 2MB
        ↓
/etc/default/grub 加 memmap=2M#0x地址（用 #，加 nokaslr）
        ↓
sudo update-grub && sudo reboot
        ↓
验证：cat /proc/cmdline + cat /proc/iomem | grep
        ↓
看到 Persistent Memory (legacy) → 完成
        ↓
（卡死则 GRUB 按 e 删掉 memmap 参数临时启动）
```

## 九、常见问题速查表

| 现象 | 原因 | 解决 |
|---|---|---|
| 改完参数卡空白壁纸 | `$` 被 GRUB 当变量解析 | 改用 `#`，加 `nokaslr` |
| 卡在 GRUB 编辑界面出不来 | 编辑的是 `Deepin Restore` 项 | 按 Esc 回菜单，选 `Deepin` |
| MemTest86 屏蔽后仍报错 | 它不读内核参数 | 用 `cat /proc/iomem` 验证 |
| `dmesg` 查不到 memtest 结果 | 内核未编译 `CONFIG_MEMTEST` | 以 iomem 结果为准 |
| apt 无法获取锁 | 更新器占用 dpkg | 关闭更新器或删除 lock 文件 |
| U 盘写完后打不开 | 正常现象（Linux 核心） | 需要时用 Reformat USB drive 还原 |
| 测试中途自动停止 | 触发错误上限 | 选项里把错误限制改为 100000 或禁用 |
